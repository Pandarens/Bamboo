# Свой раннер для суточного прогона

Нужен ровно для одного: прогнать замер бюджета сутки подряд. У раннера
GitHub задание убивается на шести часах — это жёсткий предел, обойти его
нечем. У своего предел пять суток.

Всё остальное — сборка, тесты, получасовая проверка памяти, выпуск —
идёт на раннерах GitHub и своей машины не требует.

## Сначала о риске

Раннер выполняет код из репозитория на вашей машине, с правами того, кто
его поставил. На **публичном** репозитории это известная опасность:
pull request из чужой копии выполнится у вас дома. GitHub прямо
не рекомендует такую связку.

В Bamboo защита сделана устройством, а не настройкой: суточный процесс
(`.github/workflows/budget-daily.yml`) запускается **только** по расписанию
и вручную, события `pull_request` у него нет. Раннер берёт лишь те задания,
которые на него нацелены, — значит чужой код до него не дойдёт.

Одно правило, которое нельзя нарушать: **ни один процесс с `pull_request`
не должен получить `runs-on: self-hosted`**. Сейчас таких нет — `ci.yml`
идёт на раннерах GitHub, и так должно остаться. Если однажды понадобится
иначе, сначала включите в настройках репозитория одобрение рабочих
процессов для всех сторонних участников (Settings → Actions → General →
Fork pull request workflows).

## Установка

Три шага. Всё делается один раз.

**1. Взять команды у GitHub.** Откройте
[Settings → Actions → Runners → New self-hosted runner](https://github.com/Pandarens/Bamboo/settings/actions/runners/new)
и выберите Windows x64. GitHub покажет готовый набор команд с одноразовым
токеном регистрации — токен живёт час.

**2. Выполнить их в PowerShell.** Они скачают раннер в папку `actions-runner`,
проверят контрольную сумму и настроят его. На вопрос про метки можно
ответить пустым — метка `self-hosted` ставится сама, а именно её и ждёт
рабочий процесс.

**3. Поставить службой,** чтобы раннер жил без открытого окна.
На Windows это делается прямо при настройке: `config.cmd` в конце
спрашивает «Would you like to run the runner as service?» — ответьте Y.
Если на этот вопрос ответили N, перенастройте: `config.cmd remove`,
затем `config.cmd` заново.

Прежняя редакция этого файла советовала `svc.cmd install` — такого
скрипта в Windows-раннере не существует, это способ для Linux и macOS
(`svc.sh`). Проверено по документации GitHub.

## Проверка

После установки раннер появится в
[списке](https://github.com/Pandarens/Bamboo/settings/actions/runners)
со состоянием Idle. Запустить прогон, не дожидаясь расписания:
Actions → «Бюджет за сутки» → Run workflow.

Прогон займёт сутки. Отчёт останется во вкладке Actions как артефакт
и будет храниться три месяца.

## Если раннера нет

Ничего не сломается. Суточный процесс просто не запустится: задание
подождёт свободного раннера и через сутки отменится само. Получасовая
проверка памяти на раннерах GitHub продолжит работать как работала.

И главное — суточный замер есть и без всякого раннера. Bamboo меряет
собственный бюджет сам, прямо на вашей машине, и показывает результат
в разделе «Настройки». Он даже точнее: считает под настоящей нагрузкой,
с настоящим числом процессов и настоящими открытыми окнами, а не
на стерильном раннере. Раннер нужен для того же замера в CI — чтобы
превышение роняло сборку, а не оставалось на совести человека, который
заглянет в настройки.
