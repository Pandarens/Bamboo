# Bamboo

[![CI](https://github.com/Pandarens/Bamboo/actions/workflows/ci.yml/badge.svg)](https://github.com/Pandarens/Bamboo/actions/workflows/ci.yml)

Наблюдает за Windows, объясняет, что с ней происходит, и оптимизирует —
обратимо и без плацебо.

Bamboo отвечает на вопросы, на которые не отвечает диспетчер задач: почему
браузер занимает восемь гигабайт, кто на самом деле забил диск, из-за чего
система подвисла минуту назад, чего не хватает игре, когда проседают кадры,
и сколько секунд загрузки стоит каждая запись автозагрузки. Каждое действие
записывается в журнал и откатывается.

Полное техническое задание — [bamboo-spec.md](bamboo-spec.md).
Чеклист по этапам — [PROGRESS.md](PROGRESS.md): все этапы дорожной карты
закрыты, открытых пунктов нет.

## Установка

Скачайте `bamboo-agent.exe` со [страницы выпусков](https://github.com/Pandarens/Bamboo/releases)
и запустите. Установщика нет: это один файл, он никуда себя не прописывает.

Через scoop:

```
scoop install https://raw.githubusercontent.com/Pandarens/Bamboo/main/packaging/scoop/bamboo.json
```

**Windows покажет предупреждение SmartScreen** — это ожидаемо. Файл
не подписан: проект открытый и бесплатный, сертификат подписи кода стоит
денег, а самоподписанный от SmartScreen не спасает. Взамен подписи у каждого
выпуска есть подтверждение происхождения GitHub (кем, из какого коммита
и каким прогоном собран файл) и SHA-256 в описании.

Запускать лучше от администратора: без прав Windows не отдаёт историю
загрузок, здоровье накопителя и имена задач планировщика. Bamboo при этом
не показывает пустоту — он говорит, чего именно не хватает. В «Настройках»
есть автозапуск через задачу планировщика с наивысшими правами:
подтверждение нужно один раз, при включении.

Bamboo стартует в трее. Двойной щелчок по значку открывает окно,
одиночный — виджет.

## Что умеет

**Подвисания.** Ловит момент, когда система замерла, и называет виновника,
снятого **в ту же секунду** — с именами и скоростями. Смотреть потом
бесполезно: пока откроется диспетчер, виновник уже разошёлся. Три
различимые причины: очередь к накопителю, время в драйверах, нехватка
памяти с вытеснением.

**Долгая загрузка.** Windows после каждой загрузки записывает, какой
компонент сколько её задержал. Bamboo сводит это с автозагрузкой
и показывает измеренную цену каждой записи: «Telegram задержал загрузку
на 10 с» — с выключателем рядом. Не гадание, а число из журнала
диагностики.

**Рост памяти.** Столбец, которого нет в диспетчере задач: не сколько
памяти занято, а растёт ли она и как быстро. Подозрение на утечку
появляется только после часов наблюдения — раньше это было бы гаданием.

**Кто занимает диск.** Живой список по программам, а не по процессам:
браузер работает с диском из десятка процессов, и каждый по отдельности
выглядит невинно. Любого можно придержать — обратимо.

**Анализ игры.** Выбираете игру из списка (Bamboo сам находит библиотеки
Steam и Epic), записываете сеанс — и получаете графики процессора, памяти,
видеокарты и диска за всё время плюс вывод, что упёрлось в потолок.
Советы противоположны по причине: при упоре в видеокарту закрывать
программы бесполезно — помогут настройки графики; при упоре в процессор —
наоборот.

**Игровой режим.** Отдаёт процессор и память тому, что на экране, фоновое
уводит в экономичный режим. Discord, Steam и OBS не трогает. Выключение
возвращает всё как было.

**Автопилот** (по умолчанию выключен). Пока вас нет за компьютером десять
минут, придерживает шумную фоновую работу; первое движение мыши возвращает
всё до последнего процесса. Каждое действие — в журнале. Если агент упал,
не успев вернуть, — вернёт при следующем запуске.

**Действия над процессами.** Экономичный режим, приоритет памяти,
придержание диска, завершение — по правой кнопке. Отказ от предложения
дважды — и Bamboo не предложит его больше никогда.

**Обновления.** Сам проверяет выпуски на GitHub при запуске и раз в сутки,
ставит по вашей кнопке. Тем, кто на выпуске, беты не предлагаются.

**Свой расход.** Bamboo меряет собственный рабочий набор, процессор
и запись на диск и показывает против пределов, которые сам себе назначил
(раздел 4 ТЗ). Утилита, которая считает чужие ресурсы и молчит про свои,
занимается двойной моралью.

**Два языка.** Русский и английский, переключается в настройках,
по умолчанию берётся у системы.

## Чего Bamboo не делает и не будет

Не «чистит» оперативную память, не отключает службы пачками,
не «дефрагментирует реестр», не «ускоряет интернет» и не рисует выдуманный
балл здоровья системы. Всё это либо не работает, либо изнашивает
накопитель, либо и то и другое (раздел 11.5 ТЗ). Пустой список предложений —
нормальный исход: утилита, которая всегда находит десять проблем, набивает
себе цену.

## Как устроены действия

Ни одно действие не выполняется без записи обратного рецепта в журнал.
Порядок жёсткий:

1. Проверка политикой — можно ли вообще трогать эту цель
2. Снятие состояния «до». Не сняли — действие отменяется
3. Запись в журнал **до** самого действия
4. Действие
5. Подтверждение или отметка о неудаче

Сверх того:

- перед остановкой и отключением службы создаётся **точка
  восстановления** — и успехом считается появившаяся точка, а не удавшийся
  вызов: Windows молча пропускает создание, если свежая точка уже есть;
- **триггерная служба не отключается никогда**: внешне она «ручная»,
  но просыпается сама по событию, и после отключения человек получит отказ
  чего-то постороннего, не найдя связи. Угадать триггерность по имени
  нельзя — она есть даже у планировщика заданий;
- системное ядро, средства защиты и инфраструктура — в неизменяемом белом
  списке, их не трогает даже прямой приказ.

## Сборка

Нужен Rust stable и MSVC Build Tools с Windows SDK.

```bash
cargo build --release -p bamboo-agent
```

Отладочная утилита в терминале:

```bash
cargo run --release -p bamboo-cli -- snapshot
```

| Команда | Что делает |
|---|---|
| `snapshot` | загрузка, память, топ потребителей и топ по записи |
| `watch` | то же непрерывно, с адаптивной частотой опроса |
| `disk` | накопители, их здоровье и расход ресурса |
| `boot` | время загрузки и что его удлиняет |
| `power` | пробуждения из сна и их причины |
| `leaks` | процессы с растущей памятью по живому ряду наблюдений |
| `trace --for 30` | короткоживущие процессы, невидимые для опроса |
| `trace --dump` | сброс ретроспективного буфера видеорегистратора |
| `record --out F` | записать трассу в файл для анализа |
| `diff` | что появилось в системе с прошлого снимка |
| `optimize` | что было бы сделано — ничего не меняет |
| `optimize --apply` | **применить** действия, записав их в журнал |
| `journal` | журнал действий |
| `revert --id N` / `revert --all` | **откатить** запись или всё |
| `watchdog` | **проход сторожевого таймера** с автооткатом деградаций |
| `budget --for 60` | собственное потребление против лимитов ТЗ |

Команды, меняющие систему, выделены; остальные только читают.

## Архитектура

| Крейт | Назначение |
|---|---|
| `bamboo-core` | типы, единицы, ошибки, язык. Не знает о Windows |
| `bamboo-sys` | **весь** `unsafe` проекта: Win32/NT, ETW, реестр, службы, SMART, GPU-счётчики, HTTPS |
| `bamboo-collect` | семплирование, дельты, минутная агрегация суток в памяти |
| `bamboo-analyze` | анализаторы: утечки, подвисания, всплески, износ SSD, узкое место игры, цена автозагрузки. Не знает о Windows |
| `bamboo-store` | SQLite: история наблюдений, SMART, загрузки, трассы |
| `bamboo-etw` | трассировка: короткоживущие процессы, видеорегистратор, сессии расследования |
| `bamboo-policy` | уровни риска, белые списки, профили, обучение на отказах |
| `bamboo-journal` | транзакционный журнал действий |
| `bamboo-actuate` | исполнение с откатом, сторожевой таймер, точки восстановления |
| `bamboo-ipc` | протокол агент↔брокер |
| `bamboo-service` | брокер: служба Windows под SYSTEM |
| `bamboo-agent` | основное приложение: окно на двенадцать разделов, трей, виджет, автопилот, обновления |
| `bamboo-cli` | отладочная утилита |
| `tools/trace-replay` | прогон анализаторов на эталонных трассах |

## Инварианты

1. **Весь `unsafe` — только в `bamboo-sys`.** В остальных крейтах
   `#![forbid(unsafe_code)]`, это проверяет компилятор.
2. **`bamboo-analyze` и `bamboo-core` не знают о Windows.** Анализаторы —
   чистые функции, проверяемые тестами целиком; CI собирает их на Linux,
   чтобы нарушение не прошло.
3. **Отказ вместо оценки.** Если данных нет — сказано, чего не хватает
   и почему. Выдуманное число хуже честного отказа.

## Ресурсный бюджет

Bamboo обязан укладываться в лимиты раздела 4 ТЗ (рабочий набор, процессор,
запись на диск) — превышение считается блокирующей неисправностью.
Проверяется трижды: самозамером в самом Bamboo (раздел «Настройки»),
получасовым прогоном в CI ежесуточно и недельным суточным прогоном
на своём раннере ([как подключить](docs/self-hosted-runner.md)).
