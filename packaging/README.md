# Упаковка

Как Bamboo попадает к людям помимо страницы выпусков.

## scoop

`scoop/bamboo.json` — готовый манифест. Поставить прямо из репозитория:

```
scoop install https://raw.githubusercontent.com/Pandarens/Bamboo/main/packaging/scoop/bamboo.json
```

Чтобы Bamboo появился в общем каталоге, манифест надо подать в `scoop-extras`
отдельным запросом на слияние. Пока этого не сделано — ставится по ссылке
выше, и это работает так же.

`checkver` и `autoupdate` настроены на выпуски GitHub и на файл `sha256.txt`,
который кладёт рядом с программой рабочий процесс выпуска.

## winget

`winget/` — три файла манифеста в формате 1.6, как того требует
`winget-pkgs`. Подать их можно только через запрос на слияние в
`microsoft/winget-pkgs`, и там есть требование, которому Bamboo пока
не соответствует: **установщик должен быть подписан**. Неподписанный
исполняемый файл проходит проверку не всегда и помечается как риск.

Поэтому манифесты лежат здесь готовыми, но не поданы. Честная
последовательность такая: сертификат → подпись в рабочем процессе выпуска →
подача в `winget-pkgs`. Подавать раньше — значит тратить время
сопровождающих на то, что развернут.

## Чего здесь нет и почему

**Подписи.** Нужен сертификат подписи кода, у проекта его нет.
Самоподписанный сертификат от SmartScreen и Defender не спасает: они
доверяют не факту подписи, а репутации издателя. Ставить его ради галочки
значило бы сделать плацебо-функцию в смысле раздела 11.5 ТЗ — выглядит как
защита, ею не является.

Что есть вместо: подтверждение происхождения GitHub (кем, из какого коммита
и каким рабочим процессом собран файл) и SHA-256 в описании выпуска.

**Обещания воспроизводимой сборки.** `rust-toolchain.toml` закрепляет
`stable` — плавающий канал, а путей через `--remap-path-prefix` нет.
Провенанс отвечает на вопрос «кто и откуда собрал», а не «соберётся ли
байт в байт». Смешивать эти два обещания нечестно.
